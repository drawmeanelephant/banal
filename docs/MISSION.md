# Mission

BANAL is a beautiful, boring, local Mac notes app whose files are allowed to be excellent.

You pick a folder. You write. You put notes in folders. Most days that is Markdown. Some days it is Textile. Some days it is a Cooklang recipe. The window does not change costume.

The long argument is [`THESIS.md`](THESIS.md).

Publishing is a preference and a menu item, not an identity. When someone is ready, BANAL can compile the notes they marked and hand a static site to Cloudflare Pages. Until then the app is complete without an account, a token, or a network.

## What winning looks like

Someone who currently uses Apple Notes, Bear, or a pile of files in `~/Documents` opens BANAL and does not think about it. The type is good. The folders are the same folders Finder shows. A risotto lives next to a letter. Search is instant. Nothing nags. Six months later the same vault still opens, because the data was never trapped.

If they ever want a public site, Settings already has a Publish pane: site title, base URL, Cloudflare account and Pages project, token in the Keychain. File → Publish Site… does the rest through Boris. That day can be year two. The notes app cannot wait for it.

## What this is not

- Not Solipsist (documentation IDE, Compose, graph inspector).
- Not Boris (the compiler stays a compiler).
- Not Obsidian (no graph, no plugin mall, no daily-note religion).
- Not a SaaS (no seats, no sync we operate, no paywall).
- Not an AI notebook.

## The one structural idea

**Folders are directories.**

```
Vault/
  Inbox/
    scratch.md
  Essays/
    2026-08-18-on-folders.md
  assets/
```

If Finder and BANAL disagree, BANAL is wrong.

## Quality stance

Aim at the finish of Apple’s first-party apps and the quiet tools (iA Writer, Things, BBEdit) rather than at feature checklists. A notes app with five things done at AAA beats a notes app with fifty things at “works on my machine.”
