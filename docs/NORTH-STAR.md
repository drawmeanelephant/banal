# North Star

BANAL should feel like the old Sparrow Mail or Mailbox apps, but better.

Not because it should copy their UI. Because they made a complicated thing feel obvious, fast, tactile, and pleasurable. Same conviction. Different fate: this product cannot be acquired into a carcass. The files are yours. The Mac app is yours. Publishing is yours.

It should feel like Twitter before Twitter ruined it: a clear interaction model, a surface you can read in one glance, a product that gets out of the way.

It should have the craft of the best Tapbots applications: dense where density is useful, beautiful without being ornamental, extremely responsive, keyboard-friendly, native, opinionated. It must not depend on somebody else’s API continuing to exist.

**Metaphor:** Jonathan Ive and Marie Kondo designed a notes app and, for once, had an original idea.

Every element earns its place.

- If removing a button makes the app clearer, remove it.
- If a feature needs an explanation before it makes sense, question the feature.
- If something can be a file instead of a proprietary database, prefer the file.
- If a pane exists merely because another notes app has one, kill it.
- If an interaction can be one gesture or one shortcut instead of a settings workflow, make it one gesture or one shortcut.

A new user writes something in five minutes without learning a system. A power user finds Markdown, Textile, Cooklang, and optional publishing *under* the surface, not in the chrome.

Do not cosplay Sparrow, Mailbox, Twitter, Tapbots, or Apple. Take the qualities. Invent the BANAL version.

Beautiful independent software, allowed to survive.

Now stop writing the thesis. Make the application look and feel like that.
