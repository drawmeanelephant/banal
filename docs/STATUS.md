## What works today

- Plain names (K-1, issue #192): New notes are born as `<Title>.<ext>` — `Risotto.md`, not `2026-08-25-risotto.md` — with Finder-style collision numbering (`Risotto 2.md`). Titles keep case and accents; only what cannot be a path component (`/`, `:`, `\`) is rewritten. Retitling a plain-named note renames the file on disk when the buffer settles (selection switch, flush, quit); the editor session stays put. Legacy date-stamped files are never migrated behind the user's back — their leaf does not match the title, so retitle leaves them alone until the user renames the file themselves. Case-, accent-, and separator-only differences never trigger a rename.
- New window on same folder (H-4, issue #40): File → New Window (`⌥⌘N`) opens independent Mac windows for the same active notes folder. Each window maintains its own local UI state (selection, search query, view mode) while observing the shared `NoteStore`. Editing a note in one window propagates immediately across windows with automatic dirty-state coordination. Card: [`H-4-new-window.md`](cards/H-4-new-window.md).
- Tags as secondary filter (H-3, issue #39): Sidebar displays a quiet "Tags" section below the folder hierarchy collecting unique tags in memory from note frontmatter. Clicking a tag (e.g. `#draft`) filters the note list immediately in memory; clicking the active tag again deselects it and restores the note list. Does not introduce virtual notebooks or filesystem reorganization. Card: [`H-3-tags-filter.md`](cards/H-3-tags-filter.md).
- Quiet word count in status strip (H-2, issue #38): The window footer status strip quietly displays live word and character counts (e.g. `342 words · 1,840 characters`) in secondary typography when editing a note. Counts update in real-time in memory via linguistic substring tokenization (`.byWords`) without background timers or UI bloat. Reverts cleanly to total vault note count (e.g. `12 notes`) when no note is selected, and temporarily hosts dismissable status notifications. Card: [`H-2-word-count.md`](cards/H-2-word-count.md).
- Source checkbox toggle (H-1, issue #37): Clicking inside the `[ ]` or `[x]` prefix of a task list item (`- [ ]`, `- [x]`, `* [ ]`, `+ [ ]`) at any indentation level toggles the checkbox directly in the plain text source buffer without custom webviews or widget attachments. The toggle performs a single-character swap (` ` <-> `x`) registered with `NSUndoManager`, preserving full `⌘Z` undo and standard TextKit caret placement. Code fences and non-checkbox lines are safely ignored. Card: [`H-1-checkbox.md`](cards/H-1-checkbox.md).
- System pickers for Contacts and Files (G-4, issue #35): Edit → Insert Contact… presents native `CNContactPicker` sheet and inserts selected contact as standard Markdown `[Full Name](mailto:email)` or `[Full Name](tel:phone)`; Edit → Insert File… presents standard `NSOpenPanel`, copies the chosen file into the vault `assets/` directory (with unique collision numbering `-1`, `-2`), and inserts `[Original Filename](assets/filename)`. Text insertions preserve full `⌘Z` undo history in TextKit. Card: [`G-4-pickers.md`](cards/G-4-pickers.md).
- Drag note out to system (G-5, issue #36): Dragging note rows from the list to macOS Finder, Mail, Messages, or external apps exports real file URLs on disk (`public.file-url` / `kUTTypeFileURL`) and clean formatted plain text (`public.utf8-plain-text`) via `NoteDragProvider`. Dropping onto Finder copies the real `.md`, `.cook`, or `.textile` file directly; dropping into Mail/Messages attaches the file or inserts formatted note text; internal drag-and-drop to sidebar folders for moving notes is preserved. Card: [`G-5-drag-out.md`](cards/G-5-drag-out.md).
- Images land in `assets/` (G-1, issue #32): Dropping or pasting image files (PNG, JPEG, GIF, WebP, HEIC, SVG, TIFF) onto the editor text view copies raw images directly to `<vault>/assets/`, avoids collisions with `-1`, `-2` suffixing, and inserts relative Markdown tag `![](assets/<filename>)` at the drop point/caret with `⌘Z` undo intact (`isRichText` stays `false`). Edit → Insert Photo… opens the native system image picker (`NSOpenPanel` restricted to supported image formats) and inserts the markdown tag. Managed via `AssetManager` in `BANALCore`. Card: [`G-1-assets.md`](cards/G-1-assets.md).
- Import as copy (G-3, issue #34): File → Import… (`⌘I`) allows importing note files (`.md`, `.textile`, `.cook`, and `.txt`/`.markdown` converted to `.md`) and associated assets (`assets/` folders and images) from external directories (Obsidian vaults, Bear exports, text archives). Recursively copies files into the active notes folder on disk without proprietary metadata or database lock-in. Cleanly resolves filename collisions with numeric suffixes (e.g. `Note-2.md`), refreshes the note store, and selects the first imported note. Card: [`G-3-import.md`](cards/G-3-import.md).
- Copy As formats for Markdown, RTF, and HTML (G-2, issue #33): Edit → Copy As submenu under Edit menu with Copy as Markdown (`⌥⇧⌘C`), Copy as Rich Text (`⌥⌘C`), and Copy as HTML. Synchronous in-memory conversion via `CopyAsConverter` in `BANALCore`. Markdown copies raw plain text markdown; Rich Text renders styled `public.rtf` adhering to SF Pro typography (headings, bold, italic, lists, code fences, and clickable links); HTML renders clean semantic markup to `public.html` and `public.utf8-plain-text`. Converts active text selection if present, or entire note if nothing is selected. Standard `⌘C` (Copy) is completely untouched. Card: [`G-2-copy-as.md`](cards/G-2-copy-as.md).
- System furniture and accessibility audit (F-7, issue #31): VoiceOver coverage across Sidebar (folder tree and note count announcements), Note List (rich spoken metadata including folder paths, recipe badges, published badges, relative timestamps, and previews), Editor (title, tags, view switcher, and NSTextView .textArea role), Recipe Read (clean ingredient, cookware, and numbered step announcements), Settings (explicit accessibility labels and hints across General, Editor, and Publish panes), and Vault Picker. System Manners support: `@Environment(\.accessibilityReduceMotion)` suppresses sliding transitions; `@Environment(\.colorSchemeContrast)` renders crisp 1pt separator borders. System test brief: [`TESTING-SYSTEM.md`](TESTING-SYSTEM.md). Card: [`F-7-system-sit.md`](cards/F-7-system-sit.md).
- Three columns: sidebar ~200pt, list ~280pt, editor takes the rest. Below ~880pt window width the sidebar collapses automatically (restored past ~920pt) so 720×520 shows list + editor cleanly
- Toolbar: the filter name (Notes / Published / folder / #tag) rides inline in the title bar and search is the native toolbar field (`.searchable`) at the window's trailing edge. The list column has no header row — its rows start level with the sidebar's, and the reclaimed header height goes to content. ⌘F focuses the field (macOS 15+; on 14 it still filters). Esc clears.
- List rows: title, two-line snippet, relative date, globe if published
- Editor: title + one quiet metadata row (date, published, tags). Body is a page

- Warm first run (issue #177): the vault picker shows the app icon, “Notes are plain files in a folder you own,” and on true first run makes “Use Documents/BANAL Notes” the default button. A vault the app just created (or an empty folder picked in the powerbox) is seeded with one deletable `Welcome.md` via `VaultSeed` (BANALCore, unit-tested) — never into a folder with notes, never recreated after deletion — and opens selected with the caret ready. Editor empty state pairs the ⌘N sentence with a New Note button. Settings → General footer states the folder is ordinary files (Finder / iCloud Drive / git).

### Exception to the product table: verification tooling

The product table stays as written. Two surfaces exist outside it as *verification* tooling, not features, and grow only with restraint (issue #204 thread):

- `banal` CLI (`Sources/BANALCLI`): read-mostly — `vault`, `notes`, `show`, `publish`, `doctor`. Same resolvers, store, and publish pipeline as the app. No editing, no folder ops, no watch/daemon.
- AppleScript dictionary on the app (`Resources/BANAL.sdef` + `Sources/BANALScripting`): scripted list/read/create/update/publish through the same `NoteStore` verbs. Results are JSON text. No second database, no chat surface.
